链接解析

解析链接内容

内置 yt-dlp：媒体站点（YouTube / Bilibili 等）取标题、作者、时长、简介；普通网页取标题与摘要。解析结果以「[链接] …」附在该条消息之后，让机器人能就链接内容回应。

抖音走「浏览器桥」解析：用本机 Chrome/Edge 打开一次作品页、由页面自己完成风控签名，无需登录、也无需 Cookie（要求系统装有 Edge 或 Chrome，Windows 10/11 自带 Edge）。微博、小红书等站点则会对不带 Cookie 的请求返回 403，必须提供一份 Netscape 格式的 cookies.txt 才能解析（在浏览器里登录对应网站后用扩展导出一次，不必登录也能解析的站点则留空即可）。文件不存在或留空时按原样走匿名请求，这些站点会解析失败并给出提示。

固定提示（不经过大模型）

私聊与群聊都生效：群里不必 @ 机器人，只要消息里有链接就会回固定提示，并把解析结果（推文卡片 / 视频 / 文件）发回当前聊天。提示语由这里写死，不调用大模型。关掉「模型仍接话」后，带链接的消息就只回提示与解析结果，不再烧 token。

下载并回发（谨慎）

开启后会向真实聊天发送文件，请谨慎。任何含链接的消息（私聊 / 群里不必 @ 机器人）都会下载回发，不限「触发回复」的那条。

微信对单文件有体积上限，且随会话类型不同：自聊 / 文件传输助手最宽松（高速传输可达 10 GB），普通聊天较严（旧版 100 MB）。设得过大容易下载到发不出去的文件；默认 100。

附件没发成功时最多再试几次，默认 2。两个方向都用这个次数：微信明确拒绝（附件压根没粘上去）会整条重来；附件粘进去了、但回车没被微信接受（大文件粘贴后微信还要先拷原始文件、生成卡片，这期间的回车会被丢掉）只补按回车、不重新粘贴，所以不会重复发送。调大更耐折腾，代价是发送失败时会多占一会儿发送通道。

「发送文件」按钮方式：程序点微信输入框上的文件按钮，在弹出的系统对话框里直接填入文件路径再确认。它不截屏、不 OCR，约 1 秒完成，比剪贴板粘贴更稳（剪贴板方式依赖截屏找输入框，窗口一缩到托盘就会失败）。默认自动：先试按钮方式，不行再退回剪贴板。仅在 wechatauto 后端生效。

下载目录总占用超过上限时，每次下载完成后自动删除最旧的文件，直到降到上限以内（正在下载/发送的文件不会被删）。默认 1024 MB（1 GB）；填 0 表示不限制。

X（Twitter）推文卡片

检测到 X / Twitter 推文链接时，本地把推文渲染成一张图片（头像、昵称、认证、正文、配图）发回聊天；推文含视频时还会把视频下载下来一并回发。需先开启上面的「下载并回发」。
